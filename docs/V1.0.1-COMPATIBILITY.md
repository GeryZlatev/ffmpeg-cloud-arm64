# v1.0.1 candidate compatibility and provenance

This is an additive candidate, not a tag or release. v1.0.0 remains at
`6b4bb32dbbf7eaba6b7545d92a33cbae6e492e4c`. FFmpeg 7.1.5, zimg 3.0.6,
x264 `b35605ace3ddf7c1a5d67a2eb553f034aef41d55`, the ARM64 Alpine image,
musl and every existing APK/source pin remain unchanged.

## Capability audit before allowlist changes

`build/baseline-v1.0.0/` retains the release's capability listings, enabled
configuration and 84 functional assertions, plus the original source/package
locks. The evidence comes from Gate 1 run 35203128428 and the unchanged v1.0.0
release assets. `provenance.json` records their hashes, commit and binary sizes.
The candidate rejects removal of any listed capability, enabled CONFIG component,
old configure option or source/package pin. `scripts/verify.py` is unchanged;
the SDR, Main10 SDR, HLG and PQ regressions still execute before the new tests.

Exact configure additions (all prior list members retained):

| Area | Addition | Reason |
| --- | --- | --- |
| External library | `--enable-libdav1d` | Actual CPU software AV1 reconstruction |
| Encoders | `mjpeg` | Application JPEG thumbnails |
| Decoders | `libdav1d,vp9,mp3,alac,mjpeg` | Requested inputs; MJPEG verifies generated JPEGs |
| Muxers | `image2` | JPEG file output |
| Demuxers | `matroska,mp3,image2` | WebM/Matroska VP9/AV1, standalone MP3, JPEG validation |

The existing MOV demuxer handles AV1/ALAC in MP4/M4A. All built-in parsers and
filters remain enabled, including AV1/VP9/MPEG-audio parsing and thumbnail
select/scale/format. No unrelated encoders, networking or hardware acceleration
are enabled. WebM container support does not promise unrelated audio codecs.

FFmpeg 7.1.5's built-in `av1` decoder exists, but `libavcodec/av1dec.c` returns
ENOSYS without an initialized hardware accelerator. Its internal selections
(`atsc_a53`, `cbs_av1`, `dovi_rpudec`, transitively `cbs` and `golomb`) do not
provide software reconstruction. The diagnosis used the actual locked release
archive, SHA-256 `de668509caf9e35e3cd162473441fdb29538c6d96ed080292b3cf9e6fc5d558f`.
The candidate enables `libdav1d`, not the hardware-only native `av1` decoder.

## dav1d source and build

Canonical project: https://code.videolan.org/videolan/dav1d

The current stable tag at selection was **1.5.4**, resolved through annotated tag
`191bdda98ec3c68137754dc97da1db34043d7cd4` to commit
`54706fc6bc0cdecab7e9593974a4039cc038fca7`, using canonical `git ls-remote --tags`.
An older web-search snapshot listing 1.5.3 was not used as the release authority.
The downloaded source's NEWS and Meson version agree with 1.5.4.

Source URL:
https://code.videolan.org/videolan/dav1d/-/archive/54706fc6bc0cdecab7e9593974a4039cc038fca7/dav1d-54706fc6bc0cdecab7e9593974a4039cc038fca7.tar.gz

SHA-256: `9edb11a2108b375cc58370354e705feebc93430bb780130363815c1e1ac0c250`.
This is a content-hashed canonical archive; no dav1d signature verification is
claimed. FFmpeg's existing GPG verification is retained without changes.

Exact Meson options are authoritative in `build/dav1d-configure.json`:

```sh
meson setup build --prefix=/work/prefix --libdir=lib --default-library=static --buildtype=release --wrap-mode=nodownload -Db_lto=false -Dbitdepths=8,16 -Denable_asm=true -Denable_tools=false -Denable_examples=false -Denable_tests=false -Denable_seek_stress=false -Denable_docs=false -Dtestdata_tests=false -Dfuzzing_engine=none -Dxxhash_muxer=disabled
ninja -C build -j2
ninja -C build install
```

Meson **1.8.1-r0** and Samurai **1.2-r7** (Alpine's Ninja-compatible `ninja`
provider) are build-only, SHA-256-pinned Alpine APKs. Their recipe commits are
`515fbe87842544039e7ca3761f19aef703a12b72` and
`be0833caee3020f089f02c5d7223e971a9a11ffb`, respectively. Dependencies are only
the already-pinned Python 3.12 and musl. No floating package resolution occurs.
Both build tools declare Apache-2.0 and are not linked into the runtime.

Existing CFLAGS/CXXFLAGS/LDFLAGS, armv8-a baseline, prefix maps, fixed epoch and
offline native ARM64 containers apply. Assembly remains enabled, with upstream
runtime CPU dispatch for newer ARM extensions. `bitdepths=8,16` retains 8-, 10-
and 12-bit decoding. Audit checks require ARCH_AARCH64, HAVE_ASM, CONFIG_8BPC
and CONFIG_16BPC in the generated configuration. Tools/examples/tests/docs are
excluded from the installed library build; FFmpeg integration fixtures test the
result. `--wrap-mode=nodownload` prevents fetching external test subprojects.

## Static linkage and license inventory

`libdav1d.a` is the only new external media library. Its source and build recipe
are included in Corresponding Source. The GPL-enabled FFmpeg/x264 configuration
remains; no GPL-version switch or nonfree option is introduced. The dav1d source
uses BSD-2-Clause; its exact COPYING is shipped as `dav1d-BSD-2-Clause.txt`
(SHA-256 `dd92c3c2247c5651606fc23a5e2d6a1ebc5ace9a3e49cbde0e12f05ad1cb1ee5`).
The upstream `doc/PATENTS` is shipped as `dav1d-AV1-PATENTS.txt`
(SHA-256 `335eca574598bf4ca181b12f708d6669e5a5e78c8e1513e5b35fa1f03901484b`).
These are retained notices, not a claim of patent clearance or legal compliance.

The only additional approved compatibility input is `/usr/lib/libdl.a`, supplied
by the **already-pinned musl-dev-1.2.5-r12**, package SHA-256
`576f4aabcfa01d10d6baa2d5d87de436b76e58ae76eedf9db7627051365e1fe3`.
It is exactly eight bytes (`!<arch>` plus newline), SHA-256
`f0a17a43c74d2fe5474fa2fd29c8f14799e777d7d75a2cc4d11c20a6e7b161c5`.
It contains no members and contributes no object code. Dav1d's Linux Meson
dependency discovery adds `dl`; its actual dlsym workaround is glibc-guarded.
Musl remains the existing runtime provider, with its existing source and notices.

`scripts/static_link.py` requires the pinned dav1d archive path, checks libdl's
exact empty bytes and resolved path, and rejects any libdl extracted member.
It runs before functional tests and again during packaging. Every other
unexpected archive remains a hard failure. Static ELF interpreter/DT_NEEDED
checks remain unchanged. An unexpected input requires investigation and approval;
it is never added automatically.

## Functional and reproducibility evidence

See `fixtures/README.md` and `fixtures/manifest.json` for legal synthetic media,
exact authoring commands/tool hashes and repeat-generation evidence. Fixture
encoders are never runtime or native-builder dependencies.

Each clean build performs the old 84 assertions, full baseline capability/config
superset checks, AV1 CPU decode with forced libdav1d and hardware disabled,
24-frame/dimension checks, lossless VP9 pixel equality, MP3/ALAC 48,000-sample
decode checks and AAC/MP4 roundtrips, plus frame selection to MJPEG/image2 and
JPEG decoding back to raw pixels. It records commands, probe output and hashes.

The two independent native builds must produce byte-identical ffmpeg and ffprobe.
`size-comparison.json` reports candidate bytes/hashes and deltas against v1.0.0
(ffmpeg 10,425,456 bytes; ffprobe 10,367,376 bytes). Success is established by
the resulting Gate 1 evidence, not by this recipe or local syntax checks alone.
